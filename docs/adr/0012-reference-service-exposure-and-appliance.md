# ADR 0012: Expose one reference service through a libvirt lifecycle hook

- Status: accepted for M8 software validation
- Date: 2026-07-28

## Context

The empty-host principle requires Jellyfin to run inside its dedicated service
VM, but LAN clients still need a reviewed route to the application. Installing a
reverse proxy, container runtime or Jellyfin process on the hypervisor would add
host services and a second application lifecycle. A permanent static DNAT rule
would also keep forwarding traffic when the VM is absent and could silently
point at a different future guest.

Libvirt's generated nftables policy rejects unsolicited guest input, so DNAT
alone is insufficient. Editing or flushing libvirt's complete table would make
the project responsible for rules it did not create.

## Decision

M8 exposes only `svc-jellyfin` TCP/8096. The M7 service spec and global allowlist
must both contain the same endpoint.

A `qemu.d` hook tracks the reviewed domain's active lifecycle in a root-only
runtime directory. Reconciliation owns one dedicated DNAT table and inserts
only comment-marked accept rules into libvirt's `guest_input` chain. Existing
marked handles are removed before every reconciliation; unrelated rules and
tables are never flushed or rewritten.

The LAN interface is selected from observed IPv4 default routes. Exactly one is
required unless an explicit override names one of the observed defaults.
Virtual bridges, taps, tunnels, loopback and container bridges are refused.

The hook is installed as a static shellcheckable script with empty stdout. Its
Python runtime validates the root-owned JSON contract before touching nftables.
Hook updates require every libvirt domain to be stopped before libvirt is
restarted.

Inside the VM, Jellyfin is installed directly on Debian 12 through `extrepo`.
Remote root shell scripts and container engines are rejected. Local service and
HTTP health checks complete the role; interactive first-run configuration stays
manual and private.

## Consequences

- The hypervisor has no Jellyfin listener or application package.
- Exposure exists only while the reviewed domain has an active hook marker.
- A failed exposure transaction fails the VM start and rolls back only project-
  owned rules.
- HTTPS, discovery, DLNA and future service ports remain closed.
- Multiple default routes require an explicit reviewed interface choice.
- Jellyfin upgrades follow apt repository policy inside the guest and are not
  pinned to an unreviewed arbitrary version in Git.
- The first hook install and contract changes require planned VM downtime.

## Rejected alternatives

- **Host reverse proxy:** adds a listening host service and TLS/application
  lifecycle to the hypervisor.
- **Docker or Podman in the service VM:** creates a second storage, network and
  update control plane for the reference appliance.
- **Permanent DNAT independent of VM state:** can forward to a missing or reused
  guest address.
- **Flush and recreate libvirt nftables tables:** assumes ownership of rules
  generated by another system.
- **Expose every Jellyfin default port:** discovery and DLNA are unnecessary for
  the first reviewed LAN path and increase attack surface.
